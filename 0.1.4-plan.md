# 0.1.4 — two players: push/pull the hole, energy

Goal: two players act on the shared hole. Each can push or pull it vertically,
spending energy; each has a small constant recharge. A player may be a human or a
bot. Players have different tasks (0.1.3) and compete on `solvedCount`.

Parent: `0.1.0-plan.md`, `0.1.1-plan.md`, `0.1.3-plan.md`.

## Player state (owned by player.js)

```
players: [
  { id: 0, isBot, force,          // signed px/s^2 impulse target, set by wheel/slider
    energy, energyMax, recharge,   // from settings.storage
    active,                       // true while mouse/touch held
    solvedCount, currentTask }     // task assigned to this player
]
```

Both players share one hole; forces sum.

## Force application

- Force magnitude `F` is set per player by mouse wheel or a slider, range
  `[-FMAX, FMAX]` (default FMAX 400). Sign is push (+) / pull (-) along +y.
- Energy cost while active: `cost = |F| * holeMoveEnergyCost * DT` (from 0.1.1).
  If `energy < cost`, force is scaled to `energy / (holeMoveEnergyCost*DT)` and
  energy goes to 0; otherwise energy -= cost.
- Recharge: `energy = min(energyMax, energy + recharge*DT)` always, with
  `recharge` default 5 energy/s.
- Net acceleration on the hole: `a = (F0*active0 + F1*active1) / holeMass`
  (holeMass default 1). Integrate into `hole.vy`, clamp to `holeMaxSpeed`, then
  integrate position. This replaces the direct speed-cap move from 0.1.0 when
  two-player mode is on; single-player drag (0.1.0) remains the fallback when
  both players are inactive.

## Input

- Player 0: left mouse button drag sets force via wheel; hold to activate.
  Touch on the left half of the screen activates player 0.
- Player 1: right mouse button or a dedicated slider; hold to activate.
  Touch on the right half activates player 1.
- Each player has a checkbox "is bot" in settings. When checked, that player's
  input is generated by `botStep(player, DT)` instead.

## Bot (player.js)

Simple and legible: a bot wants the hole where its own task is best served.
```
desiredY = task.side == 'left' ? H*0.35 : H*0.65   // hole low helps left? tune
force = clamp((desiredY - hole.y) * Kp, -FMAX, FMAX)
active = energy > 0.1*energyMax
```
Tune `Kp` so a bot is competent but beatable. Bot uses the same energy rules.

## Tasks per player

Each player gets its own current task from the same generator. `solvedCount` is
per player; the status bar shows both. A solve by either player counts for that
player only.

## Validation

- L1: with one player active, hole accelerates and energy drains; release stops
  force; recharge refills.
- Manual pass: two bots with opposite desired holes oscillate and settle; energy
  never goes negative; a bot with empty energy stops applying force.
