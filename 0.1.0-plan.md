# 0.1.0 — core field: split chamber, movable hole, balls

Goal: a playable sandbox. A rectangular field is split vertically by a wall with one
movable hole. Balls bounce without friction in both chambers and pass through the
hole. The user drags the hole. No tasks, no players, no scoring yet — this is the
physics and render base every later plan builds on.

## Units

| name | meaning |
|---|---|
| px | canvas pixels; world == screen, no camera |
| s | sim second, fixed `DT = 1/60` |
| u/s | ball speed, default 120–260 px/s |
| r | ball radius in px, default 8 |

## World

- Canvas fills the viewport (`#c`). Playfield is the full canvas.
- Central wall is the vertical line `x = CX = W/2`, thickness `WALL_T = 4`.
- Hole is a gap in that wall: vertical interval `[holeY - holeR, holeY + holeR]`.
  `holeR` default 48, clamped to `[16, H/2 - 16]`.
- Outer walls: left, right, top, bottom. Balls reflect off all of them.

## State (owned by sim.js)

```
balls: [{ x, y, vx, vy, r, color }]
hole: { y, targetY, vy }
settings: { ballR, ballSpeedAvg, ballSizeSame, ... }   // see 0.1.1
```

Preallocate `balls` to `MAX_BALLS` (default 200) and a `count`. No per-frame
allocation in step or render.

## Step (sim.js, fixed DT)

1. Move hole toward `targetY` with speed cap `holeMaxSpeed`:  
   `hole.y += clamp(targetY - hole.y, -holeMaxSpeed*DT, holeMaxSpeed*DT)`.
2. For each ball:
   - `x += vx*DT; y += vy*DT`.
   - Outer walls: reflect the velocity component that crossed; clamp position.
   - Central wall: if the ball crossed `x = CX` this step:
     - if its y-interval overlaps the hole interval, let it pass (no reflection);
     - else reflect `vx` and clamp to the wall face.
   - (Ball–ball collisions only if `settings.ballCollisions`; see 0.1.1.)
3. No friction, no drag. Speed magnitude is preserved on wall reflection.

Collision order is outer → central → (optional) balls, so a ball cannot tunnel
through the wall in one step. `DT` and speed caps keep per-step travel under one
radius; if a setting pushes travel over `r`, clamp the effective speed in step.

## Input (input.js)

- Pointer down on the wall/hole area starts a drag; pointer move sets
  `hole.targetY = pointerY` clamped to `[holeR, H - holeR]`; pointer up ends drag.
- Touch maps to the same handlers. No separate code path.

## Render (render.js)

- Clear, draw outer boundary, draw central wall as two segments above and below
  the hole, draw a subtle hole highlight.
- Draw each ball as a filled circle in its color.
- Draw hole grip (small handle) so it is visibly draggable.

## Colors

Six fixed colors: 3 cold (blue/cyan/teal) and 3 hot (red/orange/yellow). Color is
assigned at spawn. `same size` mode uses `ballR` for all; `random size` uses
`r in [ballR*0.6, ballR*1.4]`.

## Boot (main.js)

Loads settings from URL (0.1.1), spawns `INIT_BALLS` (default 60) with random
positions (not inside the wall), random velocities at `ballSpeedAvg`, random colors.
Starts the `requestAnimationFrame` loop: step then render. No game state machine
yet.

## Validation

- L1: open `index.html` via `file://`, balls bounce, hole drags, no console errors.
- Manual pass: 200 balls at max speed for 30 s with no NaN or stuck balls; hole
  drag never loses the pointer; reflection angle matches incidence.
