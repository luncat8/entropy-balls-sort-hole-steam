# 0.1.1 — settings panel and URL persistence

Goal: all tunable parameters live in a settings panel, apply live, and round-trip
through the URL so a configuration can be shared by copying the link.

Parent: `0.1.0-plan.md`.

## Settings

| key | control | range | default |
|---|---|---|---|
| `holeSize` | slider | 16–200 px (radius) | 48 |
| `holeMaxSpeed` | slider | 60–600 px/s | 300 |
| `holeMoveEnergyCost` | slider | 0–10 energy/s per speed | 1 (used by 0.1.4) |
| `ballSize` | slider | 4–24 px | 8 |
| `ballSpeed` | slider | 40–400 px/s | 160 |
| `ballSizeRandom` | checkbox | — | false |
| `ballCollisions` | checkbox | — | false |
| `ballCount` | slider | 10–200 | 60 |
| `generation` | slider | 0–5 balls/s spawn rate | 0 |
| `storage` | slider | 10–500 energy capacity | 100 (used by 0.1.4) |

`generation` spawns balls at the rate while below `ballCount`, in the chamber with
fewer balls, to keep the split balanced. New balls inherit size/color rules.

## Panel (ui.js)

- Collapsible panel, default collapsed on small screens.
- Each control writes through a single `setSetting(key, value)` that validates,
  clamps, mutates `settings`, and calls `applySettings()` (recompute derived
  values, resize balls if size changed).
- Sliders show current value next to the label.

## URL persistence

- On boot: parse `location.search`; for each known key present and valid, override
  the default. Unknown keys ignored.
- On any change: `history.replaceState` with the serialized settings. No reload.
- Serialization is sorted `key=value` joined by `&`, numbers trimmed. Booleans as
  `0`/`1`. Missing keys mean default, so URLs stay short.
- A "copy link" button copies the full URL to the clipboard.

## Validation

- L1: change each slider; reload; values restored.
- Manual pass: share a URL between two tabs; identical field; invalid param
  (`holeSize=abc`) falls back to default without console error.
