# 0.1.3 — task generation: hold a share of a color on a side

Goal: the game has a current task. A task asks the player to make one side of the
field hold more (or less) than a percentage of a color category. When the
condition holds long enough, the task is solved and a new one is generated.

Parent: `0.1.0-plan.md`, `0.1.2-plan.md`.

## Task shape

```
{ side: 'left'|'right',
  op: '>' | '<',
  pct: 50..80,                 // integer
  category: 'cold' | 'hot' | { color: <one of 6> },
  holdSeconds: 2,              // how long a hold task must stay true
  mode: 'immediate' | 'hold' }  // immediate solves on first satisfying step
```

Text form: `LEFT hold >60% COLD balls` or `RIGHT hold <40% red balls`.

## Condition

Each sim step, compute for the chosen side:

```
onSide = balls with center on that side of CX
inCategory = onSide balls whose color is in the category
fraction = inCategory / onSide   (0 if onSide == 0)
met = (op == '>' ? fraction > pct/100 : fraction < pct/100)
```

Track `holdTime`: if `met`, `holdTime += DT`; else `holdTime = 0`. For a hold
task, solved when `holdTime >= holdSeconds`. For an immediate task, solved on the
first satisfying step. On solve: increment `solvedCount`, generate a new task,
reset `holdTime = 0`.

## Generation

Random but biased to be achievable: side random; op random; pct random in
`[50, 80]` step 5; category: 40% cold, 40% hot, 20% a single random color.
Regenerate if the new task is identical to the previous one.

## State (owned by task.js)

```
currentTask, holdTime, solvedCount, taskStartTime
```

No persistence of progress in the URL (settings only).

## UI

- Status bar (0.1.5) shows the current task text, a progress ring for
  `holdTime / holdSeconds`, and `solvedCount`.
- On solve: brief flash on the winning side; no modal.

## Validation

- L1: force a condition by dragging the hole and confirm solve triggers.
- Manual pass: an empty side never solves a `>` task (fraction 0); a full side
  of the category solves a `>50%` task within `holdSeconds`.
